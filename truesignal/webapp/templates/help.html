Getting Started

TrueSignal is a self-tuning SAST agent that learns your codebase's security semantics.

1. Upload a Project

Start by uploading a .zip archive of your Java project. The system will:

  • Index all methods and their relationships
  • Run an initial SAST scan (mock mode)
  • Build a baseline of findings

2. Audit Findings

Review each finding and triage it:

  • Confirmed: This is a real vulnerability
  • Not Exploitable: This is a false positive
  • To Verify: Needs further investigation

3. Run Analysis

Once you have enough triage data, run the analysis to learn from your decisions. TrueSignal will:

  • Identify patterns in your code (sanitizers, sources, sinks)
  • Classify functions by their security role
  • Verify findings are solid before applying
  • Generate CxQL overrides for the SAST engine

Audit Workflow

Bulk Audit

Select multiple findings to triage them together:

  1. Check the checkboxes next to findings
  2. A bulk bar appears at the bottom
  3. Choose a decision and optional comment
  4. Click "Apply to selected"

Individual Audit

For detailed analysis, click "Audit" on any finding:

  • See the full taint path with code snippets
  • Review the decision history
  • Get AI-powered suggestions
  • Add your decision and audit comment

Filtering

Use filters to focus on specific findings:

  • Severity: Critical, High, Medium, Low
  • State: To Verify, Not Exploitable
  • Search: Find by ID, query name, or taint path

Frequently Asked Questions

What's the difference between "Confirmed" and "Not Exploitable"?

Confirmed: You've verified this is a real security issue that needs to be fixed.

Not Exploitable: The code path is protected by a sanitizer, input validation, or other security control.

How does TrueSignal learn from my decisions?

TrueSignal analyzes your triage decisions to identify patterns:

  • Functions that you repeatedly mark as "Not Exploitable" are likely sanitizers
  • Functions that consistently appear at the start of taint paths are likely sources
  • Functions that consistently appear at the end are likely sinks

What are "Overrides"?

Overrides are CxQL queries that the SAST engine applies automatically. They teach the engine about your custom sanitizers and sources, reducing false positives and false negatives.

Can I rollback an override?

Yes! Go to the Ledger page for any project and click "Rollback" on an override. This reverts its effects and removes it from future scans.

What's "Auto-Approve"?

When TrueSignal's confidence in a learning is very high (confidence score + triage support), it can auto-approve. You can review it before it's applied.

How do I export findings?

Click the "Export JSON" button on the Findings page. You can also filter before exporting by severity or state.

Does TrueSignal require live Checkmarx connection?

No! By default, TrueSignal runs in mock mode with a built-in naive scanner. To use real Checkmarx scans, set the CX_* environment variables.
